# Анализ прибыльности продаж Sample Superstore

Учебный аналитический проект по оценке выручки, прибыли и влияния скидок на финансовый результат розничных продаж. Анализ выполнен в Google Colab с использованием Python, pandas и SQL.

## Цель проекта

Определить, какие категории и подкатегории формируют прибыль или убыток, а также проверить связь между размером скидки и отрицательной прибылью.

## Данные

В проекте используется датасет **Sample Superstore**:

- 9 994 строки;
- 5 009 уникальных заказов;
- 793 уникальных клиента;
- основные поля анализа: продажи, прибыль, скидка, категория и подкатегория.

Исходный CSV не включён в репозиторий и исключён через `.gitignore`. Чтобы воспроизвести анализ, сохраните свой файл в `data/raw/` и укажите его путь в ноутбуке.

> Название и источник конкретного CSV следует добавить после загрузки файла. Репозиторий не утверждает происхождение или лицензию файла, пока они не подтверждены.

## Подтверждённые результаты

| Показатель | Значение |
|---|---:|
| Выручка | 2 297 200,86 |
| Прибыль | 286 397,02 |
| Маржа прибыли | 12,47% |
| Количество заказов | 5 009 |
| Количество клиентов | 793 |

Ключевые наблюдения:

- категория **Furniture** имеет маржу всего **2,49%**;
- наиболее убыточные подкатегории: **Tables** — −17 725,48; **Bookcases** — −3 472,56; **Supplies** — −1 189,10;
- **88,72% валовых убытков по строкам с отрицательной прибылью** приходится на позиции со скидкой **30% и выше**.

Под «валовыми убытками» здесь понимается сумма абсолютных значений `Profit` только по строкам, где `Profit < 0`. Этот показатель нельзя интерпретировать как долю всех заказов или как причинно-следственное доказательство влияния скидок.

## Бизнес-выводы

1. Общая прибыльность бизнеса положительна, но категория Furniture существенно уступает общей марже.
2. Подкатегории Tables и Bookcases требуют отдельной проверки цен, себестоимости, скидочной политики и условий доставки.
3. Высокие скидки тесно связаны с основной массой валовых убытков в отрицательных строках. Перед изменением политики скидок стоит дополнительно проверить результат по регионам, сегментам клиентов и подкатегориям.
4. Подкатегория Supplies также убыточна, хотя относится не к Furniture; её следует рассматривать отдельно.

## SQL-анализ

Файл [`sql/analysis.sql`](sql/analysis.sql) содержит запросы для:

- проверки количества строк;
- расчёта KPI;
- сравнения категорий;
- поиска убыточных подкатегорий;
- анализа результатов по диапазонам скидки;
- проверки доли валовых убытков, связанной со скидками от 30%.

Запросы используют синтаксис SQLite и предполагают таблицу `sales` с исходными названиями столбцов Sample Superstore. Если в ноутбуке таблица или столбцы названы иначе, их нужно заменить в SQL-файле.

## Как воспроизвести проект

### В Google Colab

1. Откройте исходный ноутбук в Colab.
2. Загрузите CSV во временное хранилище Colab или подключите Google Drive.
3. Проверьте путь к CSV в ячейке загрузки данных.
4. Выполните все ячейки сверху вниз: **Среда выполнения → Выполнить всё**.
5. Убедитесь, что итоговые KPI совпадают с таблицей выше.

### Локально

Понадобится Python 3.10 или новее.

```bash
python -m venv .venv
```

Активация окружения:

```bash
# Windows PowerShell
.venv\Scripts\Activate.ps1

# macOS / Linux
source .venv/bin/activate
```

Установка зависимостей и запуск Jupyter:

```bash
python -m pip install -r requirements.txt
jupyter lab
```

После запуска откройте `notebooks/sales_profitability_analysis.ipynb` и скорректируйте путь к CSV.

## Как экспортировать ноутбук из Google Colab

1. Откройте завершённый ноутбук.
2. Выберите **Файл → Скачать → Скачать файл .ipynb**.
3. Переименуйте файл в `sales_profitability_analysis.ipynb`.
4. Поместите его в папку `notebooks/`.
5. Перед публикацией выполните ноутбук заново и проверьте, что в выводах нет токенов, адресов электронной почты, локальных путей и других чувствительных данных.

Если размер ноутбука слишком большой, очистите только лишние промежуточные выводы. Итоговые таблицы, подтверждающие выводы проекта, лучше сохранить.

## Ограничения

- Полный CSV и ноутбук в текущую версию шаблона не передавались, поэтому структура преобразований данных и визуализации здесь не описываются как свершившийся факт.
- Вывод о скидках показывает связь, но сам по себе не доказывает причинность.
- Для управленческих решений желательно дополнить анализ временной динамикой, регионами, сегментами и затратами на доставку — только после проверки этих полей в исходных данных.
